1. 你刚才项目中有提到，本地生活服务平台主要是通过 Redis 实现高并发和缓存查询，那在高并发场景中，我们是怎么去实现线程安全的？你可以结合你的项目实践来说一下。
2. 刚才有说到分布式锁，那请问一下，设计分布式锁的时候，应该从哪些角度去考虑锁的力度，以及锁的时机（该在什么时候上锁、什么时候解锁）？你可以结合项目说一说，也可以说一下你自己的想法。
3. 那锁的粒度具体是怎么设计的？
4. 另外就是提到高并发系统，我们高并发系统里面会存在哪些性能瓶颈问题？
5. 数据库有没有可能是高并发系统里面的一个主要的瓶颈？
6. 那针对数据库所造成的并发不高、写入有延迟这类问题，我们怎么去优化数据库查询，尽量减少它在高并发系统中带来的性能问题？优化的策略可以从哪些角度来考虑？
7. 你能说一下 ReentrantLock，它其实是一种公平锁，那它是怎么实现线程之间的公平竞争的？这个公平的机制是什么样的？
8. ReentrantLock 跟 Java 里的 synchronized 关键字，在什么情况下 ReentrantLock 的性能可能会优于 synchronized 关键字？也可以讲一下它们两个的优势和劣势。
9. Java 里面涉及到多态和继承，你是怎么看待接口跟抽象类之间的关系？如果让我们去定义一个类，什么样的情况应该以接口的形式定义，什么样的情况应该考虑通过抽象类来定义？
10. 这里能讲一下 ConcurrentHashMap 的实现原理吗？它是怎么保证线程安全的？
11. 你对观察者模式跟发布订阅这两种设计模式有了解吗？
12. 那你大概讲一下观察者模式跟发布订阅模式，它们两个的特点跟区别是什么？
13. 你对 Kafka 这种消息中间件有了解吗？
14. 你使用 RabbitMQ 的具体业务场景是什么？
