1. 可以详细讲一讲这个项目的用户链路、整体的技术架构，以及里面划分的各个模块吗？
2. 这个项目整体会分成哪几个大的模块？是怎么划分的？
3. 整体的业务流程有串起来吗？比如商家入驻之后发布商品、内容，内容里关联商品下单，还有你提到的秒杀这些功能，整个链路是打通的吗？
4. 这个项目都用了哪些技术栈，分别解决了哪些问题？可以详细讲一下。
5. 你的消息队列跟缓存是怎么关联起来的？
6. 你这边用的缓存是本地的吗？
7. 企业里的缓存肯定不是本地部署的，如果是分布式场景下，缓存相关的问题会怎么处理？
8. 你可以先大概讲一下思路，如果要解决分布式场景下的缓存问题，是怎么去做的？可以用 Redis 分布式方案，或者其他方式都可以。
9. Redis 用的是什么样的分布式部署架构？是什么样的实现形式？
10. 你用 Redis 加锁的方式，在高并发场景下频繁加锁，岂不是性能会比较受影响吗？
11. 你刚刚提到消息队列是用来处理后续的一系列动作，可以大概讲一下都有哪些动作吗？你的消息队列是怎么驱动的？
12. 这个项目里面，哪些是你自己做的优化点？
13. 可以比较一下 RabbitMQ 跟 Kafka 的区别吗？
14. RabbitMQ 重点解决什么样的场景问题？它的设计思路里核心是解决哪些问题的？
15. 你这个 Agent 项目主要做了什么事情？大概解决什么样的问题？可以先大概讲一下。
16. 这个 Agent 项目有实际的应用场景吗？是你之前实习做的项目，还是其他的？
17. 这个项目里要对接知识库、监控数据，这些底层数据是什么样的输入形式？
18. 你现在里面整合了知识库、对话和运维三大功能，它们之间是怎么结合、怎么整合的？相互之间的关系是什么？
19. 你说的运维功能是什么场景下使用的？能举一个具体的 case 说明一下吗？
20. 排查出第一个问题的后续事务，这个 Agent 是自主去执行的，还是需要人工去指引？
21. 你的意思是，它发现问题之后就能直接给你一个故障归因是吗？
22. 这个故障归因目前都涉及到哪些场景、哪些维度？
23. 这个 Agent 的归因准确性，这块是怎么去做验证的？
24. 你对限流算法了解吗？
25. 令牌桶限流算法的原理是什么？
26. 其他的限流算法有了解吗？
27. 你之前用 Java 比较多，Java 的多线程编程这块了解吗？
28. Java 的线程池一般有哪些？创建线程池一般是怎么创建的？需要考虑哪些因素？一般在什么场景下会创建线程池？
29. Java 创建线程池都需要哪些核心参数？这些参数是怎么去设置的？
30. 给你一个场景：用户下单链路，下游有并发控制要求，比如不能超过 50 个 QPS，你作为入口接收下单请求，这个时候你要怎么设置你的线程池参数？
31. 线程池核心参数的设置逻辑，比如根据任务耗时、并发数去计算线程池大小，这块有了解吗？
32. 你对乐观锁了解吗？常见的乐观锁都有哪些加锁方式？
